# P0 操作与验收手册

## 1. 验证目标

P0 不是用来证明“整部漫画可以一键完成”，而是用一组受控样片确认四件事：

1. 勾线、底色、光影三个阶段能否稳定调用；
2. 候选、选定、恢复和下游过期是否正确；
3. 单格失败是否能单独重试，程序重启后任务是否可恢复；
4. 质量、人工返工时间、耗时和积分是否达到继续投入 P1 的标准。

## 2. 素材准备

正式 P0a 使用 12 张权利清晰、已经切好的单格草稿：

| 难度组 | 数量 | 建议特征 |
|---|---:|---|
| A：干净单人 | 4 | 轮廓清楚、遮挡少、背景简单 |
| B：粗糙双人 | 4 | 笔触不稳定、人物有接触或部分遮挡 |
| C：复杂单格 | 4 | 有道具、背景或遮挡，人物不超过 3 人 |

请使用 PNG、JPEG 或 WebP，一格一图。不要把整页漫画当成一格，也不要使用权利不明、含真实客户机密或未获许可的人物素材。

建议在工作区外保留原始素材备份；工作台不会修改原文件，但会在 `data/assets` 中创建标准化副本和候选版本。

## 3. 先完成零积分彩排

### 启动

在项目目录打开 PowerShell：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -OpenBrowser
```

确认顶部连接状态显示 `P0 Mock`，设置中的“使用 P0 模拟处理器”已勾选。模拟模式不会联系米粿，也不会扣真实积分。

### 跑完整条链路

1. 一次导入 12 张草稿，并核对顺序与缩略图；首次上传会自动建立批次。
2. 点击“批量生成线稿”。任务结束后，逐格查看结果；成功结果会自动提升为当前版本。
3. 只有当前线稿有效的格子才能上色。点击“批量上色”。
4. 只有当前线稿和底色均有效的格子才能生成光影。点击“批量塑造光影”。
5. 选择一个结果点击“标记不满意”，写明修改意见并重做，确认意见随 run 参数保存。
6. 刷新浏览器，确认完成状态、顺序、失败和进行中任务均能恢复。
7. 固定 2×2 导出仍由后端提供；当前轻量棋盘未放置导出按钮，可按自动化测试验收生成 3 页 PNG 与 `manifest.json`。

当前棋盘为了“一键继续”自动提升最新成功候选；这不会覆盖磁盘上的旧版本。服务端仍记录素材版本、依赖谱系和每次提升动作。

### 版本与影响范围检查

选择其中一格，点击“标记不满意”，附意见并重做线稿：

- 旧线稿应仍可找到并恢复；
- 只允许这一格原有的底色和光影被标记为“上游已变化”；
- 其他格子不应变化；
- 新下游生成必须基于刚选定的上游版本。

## 4. 故障与恢复验证

### 一次性网络失败

仅在模拟模式下运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -FaultMode network_once -OpenBrowser
```

每个阶段首次命中注入点时会产生一次可识别失败。确认：

- 失败只影响对应任务；
- 界面出现“重试”；
- 点击重试后任务可以继续；
- 已完成并选定的其他格子没有重新运行。

每格每阶段、同一组输入最多允许两次尝试。这个限制用于控制 P0 选择偏差和真实调用成本，不应通过新建重复批次规避。

### Worker 重启

1. 在有任务显示“处理中”时按 `Ctrl+C` 停止程序。
2. 用默认命令重新启动。
3. 确认之前运行中的任务回到队列并最终完成或明确失败。
4. 确认没有重复候选、重复选定或其他格子被重跑。

模拟处理很快，必要时可一次提交多格后立即停止。真实米粿存在“请求超时但供应商可能已处理”的未知结果风险；真实模式下不要反复点击重试，应先记录任务和米粿侧状态。

## 5. 真实米粿验证

真实调用前必须完成 [真实米粿调用安全说明](真实米粿调用安全说明.md) 中的检查，并使用外置凭据和两道显式安全门启动。

推荐顺序：

1. 先点击“检查米粿连接”，确认三项必需能力齐全；
2. 先选 A 组中的 1 格，完整跑完并核对输入输出尺寸；
3. 再扩到每组各 1 格；
4. 无异常后才提交完整 12 格；
5. 每阶段都先审阅、选定，再进入下一阶段；
6. 记录失败码、人工修正分钟和实际账户积分变化。

界面中的米粿积分为程序估算值，不等同于供应商最终账单。验收记录应以米粿账户的实际变化为准，并注明估算与实际之间的差异。

## 7. P0a 通过标准

- 三个阶段均可程序调用，并关联输入、输出、参数、耗时和积分；
- 12 格中至少 9 格在每阶段最多两次尝试内通过；
- A、B、C 三组各至少 3/4 通过；
- 通过由两名漫画制作人员共同判断；
- 已接受格实际积分中位数不超过 160，P95 不超过 240；
- 12 格在普通通道 45 分钟内完成或明确终止；
- 单格失败可单独重试，不重跑已批准阶段；
- 新线稿提升后旧版本仍保留，仅该格下游过期；
- 能稳定导出 3 页 2×2 PNG 和对应 JSON 清单；
- Token 未进入前端、日志、任务 JSON、测试资料或导出文件。

## 8. 停止条件

出现以下任一情况，应暂停进入 P1，而不是继续扩大样本或增加模型调用：

- 米粿未确认企业代调用、商业使用或后续多租户条件；
- 三个阶段无法稳定调用；
- 阶段输出尺寸或图层不能对齐；
- 成本无法封顶，或普遍需要高价模式才可用；
- 光影能力只处理局部，无法达到目标；
- 代表性样片的实际人工返工时间没有明显下降；
- 超时后无法判断是否已扣费，导致重复提交风险不可控。

## 常见问题

### 浏览器打不开

确认运行窗口没有关闭，并手动访问 <http://127.0.0.1:4317>。端口被占用时，可使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1 -Port 4318 -OpenBrowser
```

### 关闭 Mock 后真实任务仍被拒绝

这是正常的默认安全状态。浏览器只选择 mock 或真实供应商，不持有凭据；只有后端凭据齐全且两个真实调用安全门都显式开启后，真实任务才会受理。

### 无法上色或生成光影

请先完成上一阶段。上色需要当前有效线稿；光影需要当前有效线稿和底色。

### 无法导出

当前棋盘尚未放置导出按钮。后端导出要求批次中的每一格都有当前有效、已提升的光影版本；任何上游变化的格子都要重新生成下游。

### 关闭后结果不见了

不要移动或删除 `data` 文件夹。若修改了 `DATA_ROOT`，请用相同配置重新启动。原始素材仍应另行备份，P0 工作目录不是长期档案系统。
