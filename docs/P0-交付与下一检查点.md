# P0 交付与下一检查点

日期：2026-08-12

## 当前结论

内部单用户 P0 工作台已经完成，并通过本地模拟全链路、安全与恢复测试。当前版本可以用于一批“一格一图”的草稿，依次完成：

> 批量导入 → 勾线候选 → 人工选定 → 底色候选 → 人工选定 → 光影候选 → 人工选定 → 固定 2×2 页面导出

每张生成图都是不可变候选；选择新版会让不再匹配的下游显示为过期，恢复旧上游后，匹配的旧下游会自动恢复有效。历史导出仍保留，并会在当前选择改变后标明“已过期”。

## 已验证

- 默认模拟处理器不会访问米粿、上传图片或扣除真实积分；
- 米粿真实调用必须同时满足外置凭据和两道显式安全门；
- 实际 MCP 清单只读检查通过：9 项能力可见，P0 所需 3 项齐全；
- 勾线使用 `line_art_beautify_v4`；
- 底色使用 `coloring_v4`；
- 光影使用 `shadowing_v7`；
- MCP 参数范围已按实际工具 Schema 固定；
- 同一格、同一阶段、同一输入最多两次尝试；
- 幂等键与完整请求绑定，改变处理器、参数或输入会被拒绝；
- 批量任务和批量导入使用数据库事务，不会形成可见的半批次；
- 真实调用结果不确定时会冻结继续调用，要求先核对费用；
- Worker 重启后，已转存结果不会重新调用供应商；
- 导出会检查源文件 SHA-256，避免损坏文件与清单不一致；
- 12 格可确定性生成 3 页固定 2×2 PNG 和 JSON 清单；
- 使用实际 Token 做了不显示内容的泄漏扫描，交付目录为零命中。

当前自动化检查已扩展到 73 项并全部通过。StoryArk 3.0 已在 2026-08-13 使用 CC-BY-SA 演示素材完成一次经用户批准的 `1K × 1` 真实烟测；经典 Factory `coloring_v4` 已在 2026-08-14 完成一次真实单图烟测、供应商账单对账和既有结果恢复。证据分别见《StoryArk 真实烟测记录》和《Factory 经典链路真实烟测记录》。

## 为什么停在这里

代码闭环已经达到 P0 内部试用条件，但“画面质量是否值得进入 P1”不能由模拟图判断。下一检查点需要 12 张权利清晰、已切好的代表性草稿，以及两名漫画制作人员的独立评审；缺少这两项时，不应通过反复生成来宣称质量达标。

## 下一步所需材料

1. 12 张单格草稿：A 组干净单人 4 张、B 组粗糙双人 4 张、C 组复杂格 4 张；
2. 每张图的必要保留项、关键道具和禁改项；
3. 素材可用于内部测试与供应商处理的权利确认；
4. 两名评审人员；
5. 米粿 P0 测试的实际积分余额记录。

素材应放入本机 `samples/private`，不要上传到版本库。完成后按《P0 操作与验收手册》先跑 1 格，再每组 1 格，确认无异常后才运行完整 12 格。

## P0 通过门槛

- 至少 9/12 格通过，且 A、B、C 每组至少 3/4；
- 两名评审均认为三个阶段可以进入下一工序；
- 每格每阶段最多两次尝试；
- 每个通过格的人工修补不超过 10 分钟；
- 通过格积分中位数不超过 160，P95 不超过 240；
- 全批次 2,880 积分硬停止；
- 12 格在系统活动时间 45 分钟内完成或明确终止；
- Token 泄漏为零，版本、尺寸、重试、恢复和排版测试全部通过。

达到这些门槛后，才建议进入小说导入、人物时期设定、分镜/脚本、生图模型路由、局部返工、植字和管理后台等 P1–P4 工作。
